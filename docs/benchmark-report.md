# 测试报告测试项

被测对象是带上行口和下行口的设备，以及挂在下行口上的相机、VUT 追踪器和 PEAK-CAN 手部链路。测试项按口、业务流和供电路径分开。第 0 节记录测试主机环境。第 1 节及之后各项结果分两栏：`2026-11-06` 填本日实测，`复测` 留作后续复测。本日供电：Hub 由电脑 USB 口供电；UMI 灵巧手由 USB 口供电。

协商速率、描述符里的声明、完成字节、应用层帧率和供电效率分属不同测试项。应用层通过，不等于 USB 协商到了更高档位；USB 协商到了更高档位，也不等于应用层不丢帧。参数与术语的含义见文末附录。

## 1. 上行口 USB 3.0

上行口是被测设备朝向主机的口。USB 3.0 这一档的线速率是 5 Gbit/s。训练到 10 Gbit/s 或 20 Gbit/s 时，结果填写实际档位。

本日被测上行器件为沁恒 USB 2.0 Hub（`1a86:80a0`）。未训练到 SuperSpeed，第 1 节按实际上行 480 Mbit/s 填写，并标明未满足 USB 3.0。

## 3. 外供电 / 手机供电 / 电脑供电效率

三组测试记录同一套电参数，只是输入电源不同。外供电的输入来自适配器或外部直流源。手机供电的输入来自手机送到上行口的 VBUS。电脑供电的输入来自主机 USB 口送到上行口的 VBUS。输出是被测设备交到下行口的功率；多个下行口同时带载时，输出功率相加。

## 附录 A. 测试项含义

- **协商速率**：线已经连上，双方选定的速度档。USB 2.0 高速是 480 Mbit/s，USB 3.0 是 5 Gbit/s。
- **父口能力**：主机那个口最高能到的档。相机可以比主机口低。
- **TX / RX 通道**：来回各用了几对线。USB 3.0 通常各一对。
- **bcdUSB**：设备自己写的 USB 版本号，例如 2.10 或 3.20。
- **bmAttributes**：配置描述符里的一个字节。bit6 为 1 表示自带电源，为 0 表示从 USB 口取电。bit5 为 1 表示能把挂起的主机叫醒。
- **bMaxPower**：设备声明最多从 USB 口拿多少电流，单位是毫安。这是申请值，不是测到的电流。
- **微帧**：高速和 USB 3.0 的时间片，125 µs。1 ms 里面有 8 个微帧。
- **bInterval**：主机多久来取一次周期数据。低速和全速按 1 ms 计；高速和 USB 3.0 按 `2^(bInterval-1)` 个微帧计。
- **驱动**：内核里负责这个接口的模块。相机视频一般是 `uvcvideo`，键盘鼠标是 `usbhid`。用 `lsusb -t` 看每行末尾的 `Driver=`。
- **突发**：USB 3.0 允许连续发出的数据包个数，中间不逐包握手。长度是 `bMaxBurst + 1`，最多 16 包。
- **最大包长**：一个包最多装多少字节。
- **完成字节 / 载荷速率**：这段时间里驱动实际交出来的字节，除以真实用掉的时间。
- **波特率**：串口每一秒传多少位，和 USB 协商速率是两层。
- **采样点**：CAN 在一个位的什么位置读电平。
- **效率**：下行口交出去的功率，除以电源送进来的功率。
- **窗内帧率**：计时窗内应用拿到的完整样本数，除以实测墙钟。预热样本不计入。分母是墙钟，不是请求的秒数。
- **序号缺口**：相邻两份样本的序号差大于 1。每一档缺口计一次丢样本。
- **帧间隔**：相邻两份有效样本时间戳之差。优先用驱动或设备给出的单调时间戳；没有时用用户态取出时刻。
- **不延迟**：指帧间隔稳定落在目标周期附近，没有长时间停顿。不是线级传播时延。
- **完整画面**：一帧载荷可按约定格式解释。未压缩流要求 `bytesused` 等于宽 × 高 × 每像素字节；MJPEG 要求有 SOI `FF D8` 和 EOI `FF D9`。
- **快照**：从计时窗内抽出的静止帧文件，用于人工核对画面内容，不是吞吐数字本身。
- **VUT 预热 READY**：追踪状态属于 OK 集合，地图状态可复用或已重建，并且姿态序号在推进，且上述条件连续保持达到设定秒数。
- **融合上报轮次**：手部下位机一次完整遥测。经典 CAN 上通常是 `0x112` 编码器两帧，加上 `0x114` 触控元数据和 52 个数据段，共 55 帧。60 Hz 指这类完整轮次，不是单帧计数。

服务间隔按同一条规则换算：低速和全速的 `bInterval` 单位是 1 ms 帧；高速和 SuperSpeed 的 `bInterval` 表示 `2^(bInterval-1)` 个 125 µs 微帧。Bulk 端点没有服务间隔。

计时一律用 `CLOCK_MONOTONIC_RAW` 或驱动单调时间戳。预热样本丢弃。判定默认取目标帧率的 95% 作为下限，例如 30 Hz 取 28.5 Hz，120 Hz 取 114 Hz，60 Hz 取 57 Hz。
